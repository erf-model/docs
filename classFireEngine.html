Detailed Description

A fire engine behind the shared coupling layer.

The coupling calls, in this order:

  • verify_prerequisites() once at start-up, after its own checks of the ERF configuration and before it builds the fire grid;
  • initialize() once, with the fire grid built, then start_run();
  • read_checkpoint() on a restart, right after start_run();
  • advance() then fill_fluxes() once per step of the fire grid's level, after that level's dycore;
  • smoke_heat_per_kg(), heat_open_fraction_atm() and roof_height_atm() when it injects the lagged fluxes, at every Runge-Kutta stage of the next step;
  • write_plotfile() on the fire plotfile schedule (erf.fire.plot_int, erf.fire.plot_per), and write_checkpoint() from FireCoupler::write_checkpoint when ERF writes a checkpoint;
  • plot_var_names() once, when the coupler is constructed (before verify_prerequisites), and plot_var() each time ERF writes its own plotfile, for the fire fields that file carries.

The getters at the end (level set, reference wind, heat release) are what other surface models may read from the fire (a dust or smoke source model, for example); an engine that has none returns nullptr and those couplings do nothing.

The engine needs a surface layer at the bottom boundary.

True by default: the coupling then stops at start-up unless zlo.type = surface_layer. An engine that reads nothing from the surface layer (it takes the wind and heights from FireForcing alone) returns false and may run over any bottom boundary.

◆ plot_var_names()

virtual std::vector<std::string> FireEngine::plot_var_names ( ) const
inlinevirtual

Fire fields the ERF plotfile can carry, by name.

The names the deck may list in erf.plot_vars_* (for example "fire_phi", "fire_heat_flux"); they should start with "fire_" so they never collide with an ERF variable. The coupler asks once, when it is constructed: before initialize() and before ERF reads its plot variable lists, so the answer depends on the engine's inputs only. The default lists none.
