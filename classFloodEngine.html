Detailed Description

A flood engine behind the shared coupling layer.

The coupling calls, in this order:

  • plot_var_names() once, when the coupler is constructed (before verify_prerequisites and before ERF reads its plot variable lists);
  • verify_prerequisites() once at start-up, after its own checks of the ERF configuration and before it builds the flood grid;
  • initialize() once, with the flood grid built, then start_run();
  • read_checkpoint() on a restart from a checkpoint that holds flood state, right after start_run();
  • advance() once per step of the flood grid's level, after that level's dycore and microphysics;
  • write_plotfile() on the flood plotfile schedule (erf.flood.plot_int, erf.flood.plot_per), write_checkpoint() when ERF writes a checkpoint, and plot_var() each time ERF writes its own plotfile, for the flood fields that file carries.

The field plot_var_names() lists as name, on the flood grid.

One component, on FloodGrid::ba and FloodGrid::dm, valid until the next advance(). The coupler averages it over each atmospheric column (the grid_ratio^2 flood cells under it) and writes it into the k = 0 layer of the ERF plotfile, zero elsewhere. nullptr writes zeros.

Flood fields the ERF plotfile can carry, by name.

The names the deck may list in erf.plot_vars_*. Each must start with "flood_" (the coupler stops otherwise), so they never collide with an ERF variable. The coupler asks once, when it is constructed, so the answer depends on the engine's inputs only. The default lists none.

)
inlinevirtual

Restore the engine's state from a checkpoint on a restart.

Called only when the checkpoint holds flood state (it was written with erf.flood.enable = true) and the coupling has checked that it belongs to this run's flood grid. A restart from a checkpoint without flood state (an atmosphere-only spin-up) skips this call, and the engine continues from its initial state.

Parameters
[in]restart_chkfileThe checkpoint directory
[in]stepThe step count of the flood grid's level at the checkpoint

The default stops the run: an engine that does not implement restart says so instead of continuing from its initial state.

The engine takes the surface precipitation in FloodForcing.

True by default: the coupling then stops at start-up unless the microphysics scheme accumulates surface precipitation. An engine driven by other sources only (an inflow hydrograph) returns false.
