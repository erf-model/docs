The first problem found in a height table, or an empty string if there is none. Problems: fewer points than the layout needs (ERF format: one in each direction, USGS: two; one value in a direction is not checked further), list sizes that do not match nx and ny, a value that is not finite, x or y values that do not increase strictly (in the USGS format: the x values of each row, and the y values from row to row), and a table that does not cover the domain: each end of the x and y lists may stop at most one table spacing inside prob_lo or prob_hi (the layout of a file with one height per cell starting at prob_lo), with an allowance of 1e-3 of that spacing for rounded coordinates. Beyond the table the reader only extends the heights from its edge: linearly before the first point, and (ERF format) by holding the last value after the last point; USGS extends linearly at both ends.

Parameters
[in]is_usgsUSGS layout (x varies fastest, one x per point)
[in]nx,nytable size
[in]x,y,ztable coordinates and heights
[in]prob_lo,prob_hidomain extent
