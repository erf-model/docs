Make an ERF-format height table periodic in each direction where periodic[d] is true, so that the terrain is the same on the two faces of the domain in that direction:

  • a table with points on both faces (to 1e-3 of the table spacing) must hold the same heights on the two faces, to 1e-6 of the largest |height| (at least 1e-6 m);
  • a table with points on one face only is extended to the other face with the heights of the face it has (a table with one height per node starting at prob_lo, say, gets the heights at prob_lo again at prob_hi). A direction with a single value is constant and needs nothing. A table with points on neither face is left as it is, with a note. Returns the problem (heights that differ on the two faces), or an empty string; note describes what was done, or is empty if nothing was.
Parameters
[in,out]ttable (must pass TableProblem with the domain coverage check)
[in]prob_lo,prob_hidomain extent

[out]notewhat was done to the table, for the start-up output

The first problem found in a height table, or an empty string if there is none. Problems: fewer points than the layout needs (ERF format: one in each direction, USGS: two; one value in a direction is not checked further), list sizes that do not match nx and ny, a value that is not finite, x or y values that do not increase strictly (in the USGS format: the x values of each row, and the y values from row to row), and a table that does not cover the domain: each end of the x and y lists may stop at most one table spacing inside prob_lo or prob_hi (the layout of a file with one height per cell starting at prob_lo), with an allowance of 1e-3 of that spacing for rounded coordinates. Beyond the table the reader only extends the heights from its edge: linearly before the first point, and (ERF format) by holding the last value after the last point; USGS extends linearly at both ends. Setting require_domain_coverage to false skips only the coverage check, for building files that describe a local patch. Coordinate ordering and all format checks still apply.
