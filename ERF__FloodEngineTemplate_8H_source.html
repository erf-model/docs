6 /**
7  * @file ERF_FloodEngineTemplate.H
8  * @brief A starting point for a new flood engine: declarations only
9  *
10  * This class declares every FloodEngine method a new flood model provides.
11  * Nothing here has a body, no input selects it and nothing creates one, so it
12  * adds no code to ERF. Tests/FloodEngineExample is the smallest engine that
13  * works, and a complete engine directory to copy.
14  *
15  * To start a new engine:
16  * 1. Copy this file into the new model's engine directory (outside ERF),
17  * rename the class and the include guard, and write the bodies in a .cpp
18  * file there. Delete the declarations of the optional methods the engine
19  * does not provide (their defaults in FloodEngine then apply); a
20  * declaration left without a body fails to link.
21  * 2. Read the model's inputs under its own prefix (flood.<engine>.* is
22  * recommended), so they never mix with the coupling's keys
23  * (FloodCouplingParams, erf.flood.*) or another engine's.
24  * 3. Register the engine in that .cpp, at namespace scope:
25  * ERF_REGISTER_FLOOD_ENGINE(MyEngine, "my_flood")
26  * (ERF_FloodEngineRegistry.H), and give the engine directory a
27  * Make.package (GNU make, FLOOD_HOME) and an ERFFloodEngine.cmake defining
28  * erf_flood_engine_add(target) (CMake, ERF_FLOOD_ENGINE_DIRS).
29  * 4. Run a restart of a coupled run against a straight run: the atmosphere
30  * and flood plotfiles must agree at zero tolerance.
31  *
32  * The call order is the one documented on FloodEngine (ERF_FloodEngine.H).
33  * ERF_FloodCoupler.cpp checks at compile time that this class declares every
34  * method FloodEngine requires (the pure virtual ones), and override checks the
35  * signature of every method declared here. The optional methods are listed by
36  * hand: a new optional method in FloodEngine is added here too.
37  */
