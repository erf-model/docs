41 // Selects how the WDM6 parameter literals are interpreted. See the LITERAL
42 // PRECISION CONTRACT comment on the constant block below for the full
43 // rationale. Namespace scope, not a class member, because a constexpr member
44 // function cannot be used in a constant expression within its own class body.
45 constexpr amrex::Real wdm6_literal (double d)
46 {
47 #ifdef ERF_WDM6_F32_LITERALS
48  // Match the Fortran as compiled today: its literals carry no kind suffix,
49  // so they are evaluated in single precision and then widened.

51 #else
52  // True doubles. Correct when the Fortran is built -fdefault-real-8.
53  return amrex::Real(d);

71  // WDM6 module parameter constants (from WRF module_mp_wdm6.F)
72  //
73  // LITERAL PRECISION CONTRACT
74  // --------------------------
75  // Every constant below is initialised through wdm6_literal() rather than
76  // written directly, because the two implementations do not agree on what
77  // these literals mean.
78  //
79  // In ERF_module_mp_wdm6.F90 the parameters are declared
80  // real(kind=kind_phys), parameter :: dimax = 500.e-6
81  // with NO kind suffix on the literal. Fortran therefore evaluates the
82  // literal as a default (single-precision) real and only then widens it to
83  // kind_phys, so the stored value carries float32 rounding permanently.
84  // All 22 parameters in that module are written this way; none is suffixed.
85  // dimax for instance is +5.00000023748725652695E-04 in the Fortran, which
86  // is bit-for-bit float32(5e-4) widened, against a true double
87  // +5.00000000000000010408E-04 here.
88  //
89  // That single 2.37e-11 difference is the confirmed root cause of the first
90  // materially failing group in the tag-frontier retreat: it clamps
91  // diameter, which drives pidep in G13e, which amplifies into psaut in G13f
92  // and on into the Milestone A and B plotfile failures.
93  //
94  // ERF_WDM6_F32_LITERALS selects which side to match:
95  // defined reproduce the Fortran-as-compiled-today values bit-for-bit
96  // undefined use true doubles, which is correct when the Fortran side is
97  // built with -fdefault-real-8 so its literals are doubles too
98  //
99  // Four constants (actk, bvtr, bvts, satmax) previously carried a hand-added
100  // 'f' suffix. That was an undocumented partial fix covering 4 of 22 and it
101  // would have silently fought a -fdefault-real-8 build. Those suffixes are
102  // absorbed here so the choice is made in exactly one place.
103  //
104  // Note r0, peaut and alpha_wdm6 have no matching Fortran parameter of the
105  // same name and value, so their correspondence is unverified; they are
106  // routed through the same helper for uniformity, not because a match is
107  // established.
108  //
109  // wdm6_literal is defined at namespace scope above rather than as a member:
110  // a constexpr member function cannot be called in a constant expression
111  // inside its own class body, because the class is incomplete until the
112  // closing brace.
