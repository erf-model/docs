Exactly de-average one line.

Given cell values t(0..n-1), produce node values s(0..n) satisfying 

1/2 ( s(k) + s(k+1) ) = t(k),    k = 0 .. n-1

exactly. The system is underdetermined by exactly one degree of freedom: the recursion s(k+1) = 2 t(k) - s(k) solves it for any seed, and changing the seed adds the sawtooth (-1)^k, which the averaging operator annihilates. So the seed is free, and it is chosen here in closed form to minimize the first-difference energy sum_k ( s(k+1) - s(k) )^2 along the line, i.e. to leave as little of that sawtooth in the answer as the constraint permits.

Exactly de-average one horizontal slice: find nodal S with avg4(S) = T to round-off, rather than the closest such field a smoothness prior will allow.

The four-node averaging operator is a tensor product of two one-dimensional two-point averages, A = Ax (x) Ay. Each of those is surjective – the line recursion above always solves – so A is surjective and an exact solution always exists; the system is underdetermined, not inconsistent, with (nx+1)(ny+1) unknowns against nx*ny equations. Separability means it can be solved in two sweeps: first Ay U = T for U (cell-centered in x, nodal in y), then Ax S = U. Both are O(N) and non-iterative.

What cannot be removed is grid-scale structure. The null space is spanned by (-1)^i a(j) + (-1)^j b(i), in which a does not vary with i, so the amplitude of the sawtooth cannot be varied along a line; rough terrain anywhere on a line leaves a signature everywhere on it. Minimizing the first-difference energy line by line, as deaverage_line does, exhausts that freedom – a globally coupled optimization over the whole null space was measured to give no further improvement. The caller is therefore responsible for deciding whether the result is usable as terrain, and for falling back if it is not.

Reconstruct one horizontal slice of nodal heights from heights that live at w-faces, reporting diagnostics and aborting if the result is unusable as terrain.

Both NetCDF initialization paths need exactly this operation and differ only in how the w-face slice is assembled (geopotential from PH + PHB for wrfinput, HGT_M for metgrid) and in what they do with the answer, so the solve and its checks live here and are called from both.

The solve is serial and covers the whole domain, so it runs on the I/O rank only and the resulting nodal slice is broadcast. Running it redundantly on every rank would cost a full-domain CG solve and several full-domain managed allocations per rank, i.e. a startup stall and a memory spike that grow with the rank count rather than with the decomposition. z_w_face_slice must be host-accessible and must hold the global slice on the I/O rank.

This is collective: every rank must call it.
