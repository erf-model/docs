Fill a staggered z-level array with a geometrically stretched grid.

zlevels must already be sized to nz+1; its length is what sets nz. The top level is assigned z_top exactly rather than by accumulation, so the array closes on the domain top to the last bit even though the sum that got there is only accurate to tol.

Solve for the geometric stretch factor that fills a domain of depth z_top with nz layers whose first is dz0 thick.

The layer thicknesses are dz0 * ratio^k, so the column depth is the geometric sum 

S(ratio) = dz0 * (ratio^nz - 1) / (ratio - 1),

and the factor wanted is the root of S(ratio) = z_top, found by Newton iteration from ratio = 1.03. The derivative is analytic, so the iteration converges in a handful of passes for any physically sensible (dz0, z_top, nz).

This is the natural construction for an idealized case, where dz0 and z_top are what the user knows a priori and the vertical distribution between them is free. It is not the right construction when a file already carries a vertical distribution worth keeping – see wrf_mean_layer_thickness in ERF_InitFromWRFInput.cpp – because one constant factor cannot represent a stretch ratio that varies with height.

A dz0 at or above the uniform spacing z_top/nz cannot be stretched to fit, since the thicknesses only grow: that case returns the uniform grid with uniform = true, rather than a factor below one that would thin the layers aloft. A single layer is the same situation for a different reason – the sum of one layer is dz0 whatever the factor is, so S has no root and its derivative is identically zero – and is answered the same way.
